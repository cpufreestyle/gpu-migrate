# GPU Migrate — 核显高占用进程迁移到独显

监控各进程对**核显 (iGPU)** 的占用，当某进程持续高占用核显时，自动把该程序的 exe 写入
Windows 图形首选项（“高性能”= 独显），程序**下次启动**即在独显上运行。

监控与命令行部分纯 Python 标准库实现（Windows 10/11），无需安装任何依赖。
只有托盘模式例外：`gpu_tray.py` 用到 `pystray` 与 `Pillow`，从源码跑
`python gpu_monitor.py --tray` 前要先 `pip install pystray pillow`；
双击 `GPUMigrate.exe` 不需要（两者已打进包里）。

 **Python 版本：3.8 及以上。** 代码不用 `match` 语句、PEP 604 注解、
 `str.removeprefix` 之类的新语法与新 API（有测试逐文件扫 AST 确认）；
 唯一需要注意的版本差异在测试侧 —— `sys.stdlib_module_names` 是 3.10
 才有的属性，测试拿不到它会退到一份内置名单，不会因此崩掉。

## 重要说明：为什么不能“原地迁移”

Windows 不支持把**正在运行**的进程迁移到另一块 GPU——GPU 首选项只在进程启动时生效。
因此本工具的做法是：

1. 检测到某 exe 持续高占用核显 → 写入注册表 `HKCU\Software\Microsoft\DirectX\UserGpuPreferences`
   该 exe = `GpuPreference=2;`（等效于 设置→系统→屏幕→显示卡→图形 里的“高性能”）。
2. 你手动重启该程序（或配置 `auto_restart: true` 让工具自动重启它），重启后即运行在独显上。

## 用法

**最简单方式：双击 `GPUMigrate.exe`** —— 直接进入托盘模式（无需 Python 环境）：
任务栏托盘出现彩色圆点图标，数字为核显总占用（绿 <30% < 橙 <60% < 红），
悬停显示核显占用、生效策略和独显温度（与 Web 面板同一句文案，
读不到温度时那行自动消失），双击图标打开实时面板（进程级核显/独显占用表），
右键菜单可暂停/恢复监控、打开面板、退出。

### 实时面板（托盘模式，双击托盘图标打开）

- **顶部汇总卡**：核显占用、独显占用、专用显存、共享显存、GPU 进程数、生效阈值。
  这六个数和托盘悬停 tooltip、`--list`、Web 面板共用同一套口径（占用取"最强引擎"，
  显存跨适配器求和），不会出现同一台机器三个读数。
  窗口拉窄时六张卡一起缩短（`pack(expand=True)` 等分一行），不会把右边几张切到视口外。
- **进程表**：进程名在最前一列，占用按 30%/60% 两档上色，配色与托盘图标同一套；默认按“活动量”(GPU% 与两列显存的最大值)排序，与 `--list`/Web 面板三面同序，点表头可按单列改排；工具栏的“复原到自动”按钮一键回到默认排序；
  双击行进详情，右键可把该程序加入"永不迁移"；详情窗里的「GPU 首选项」会在点过按钮后立刻换成新答案，不再留着打开时那一行的旧状态；末列“迁移状态”标出已设为独显的进程。表格只放得下 30 行，多出来的行不会静默吃掉——提示里会写"还有 N 行未显示"。
- **筛选框**：`Ctrl+F` 聚焦，按进程名（子串、大小写不敏感）或 PID 过滤，
  右下角提示 `显示 N/M 行`；右侧还有一个 `置顶` 开关（默认开，选择会记住）；`Esc` 先清空筛选词，再按才关窗口。
  窗口位置大小、列宽、置顶开关、筛选词、排序列都存在 `panel_ui.json`，下次开面板原样恢复；
  这份文件是手也能改的，存成 `[]`、`"abc"` 或列宽写成列表都算合法 JSON，
  程序按默认布局打开而不是把面板整个打不开。
- **底部趋势图**：最近 30 分钟核显占用折线，红色虚线是迁移阈值线 ——
  一眼看出什么时候会被判成高占用。角标时长按首末两点真实时间戳算，
  采样卡顿或休眠唤醒后点距变大，窗口多长就报多长，不按点数虚报。
  显示缩放高于 100% 时界面照旧清晰：进程一启动就按每显示器 DPI(per-monitor v2)声明自己，
  不等系统按 100% 渲染再拉伸成糊图（打包用的默认 manifest 不带 dpiAware，只能进程内声明）。
- Web 面板（端口见配置里的 `web_port`）是同一份数据的浏览器版，汇总卡、筛选框和趋势图都有；响应带 `Cache-Control: no-store`，
  每秒轮询不会被浏览器或中间代理拿旧占用糊弄人；筛选词存在 `localStorage`，刷新页面也不会丢。
  HEAD 请求与 GET 走同一套响应头（状态 200、`Content-Length` 与 GET 实际字节数一致，
  只是不回 body），健康检查、`curl -I`、浏览器预取不会再把活着的面板报成 501。
  每秒更新走的是局部刷新：只换策略行、显卡行、汇总卡、趋势图、表格体和提示这几块，输入框和滚动位置原封不动（整页 `meta refresh` 会把滚动弹回顶部、表格每秒闪一下）。
  取不到数据时页面不再装活：连续 3 秒刷不出新数据（监控进程退出、HTTP 5xx）会在页面顶部给出「连接已断开,数据停在 HH:MM:SS (监控进程可能已退出)」，恢复后自动消失；单次网络抖动不打扰，一次都没刷新成功过则说「页面加载时」。
  还有第二种更隐蔽的“装活”：请求通着(200)但快照停在旧时刻 —— 监控线程被异常
  掀翻时 Web 线程还活着，每秒发回来的都是同一份数。快照带 `snap_ts`，前端拿本地
  时钟比，超过宽限秒数显示「数据已停更, 最后更新 HH:MM:SS (监控进程可能已停止)」，数据恢复流动即消失。
  宽限秒数不写死：由服务端按采样周期算（两个周期 + 5 秒，下限 25 秒）写进页面的 `#staleafter`，
  周期调到 30s/60s 时健康监控不会被误判成死掉，周期短时灵敏度不变。
  筛选口径与托盘面板一致：只认进程名（子串、大小写不敏感）和 PID，输入 12 不会把「独显% 12.3」的行也算进来；
  页面带 `viewport`，手机上打开不会缩成蚂蚁字，表格窄屏横向滚动。
  `0.0% / 0MB / 0MB` 的噪声行不进表，和托盘面板共用同一个 `row_is_noise()` 判据（`--list` 仍给全量，CLI 是诊断用）。
  列与托盘面板一一对应（进程 / PID / GPU% / 核显% / 独显% / 专用MB / 共享MB / 迁移状态）：已经设为独显的进程会在末尾那一列标出来，看得出它为什么还挂在独显上。
  被滤掉几个会写在提示行里（`显示 34/34 行  (已隐藏 6 个 0.0% / 0MB)`），汇总卡的 `GPU 进程` 仍报真实总数。
  趋势图是内联 SVG（最近 30 分钟，每 10 秒一点，红虚线为迁移阈值），口径与托盘面板那张图一致；它跟 `history` 开关解耦，关掉 `history.jsonl` 落盘不会让界面上的趋势图一起消失。
  时间轴按时间戳算，不按点数：休眠唤醒或暂停监控后，窗口外的点整个不画，窗口内的点按真实间隔排布 ——
  以前取"最后 180 点 + 序号等距"，两个小时间的空白会被画成一段连续曲线，而角标写着"近 30 分钟"，图和标题互相打脸；窗口内凑不够两点时，空态文案会说明是"最近 30 分钟无采样数据"，而不是拿"每 10 秒一点"搪塞。
  折线、阈值线和填充是 SVG，两个文字标签是浮在上面的 HTML 层，宽面板下不会被 viewBox 拉扁；阈值线画在填充之后，折线翻上去也不会被盖住。
  小字的对比度按 WCAG AA 配：提示行、空态文案这些灰字从前是 #666a80(3.4:1) 和 #555566(2.5:1)，在深色底上基本等于没有，
  现在统一走 #8888a0(≥4.7:1)，字号也从 11px 提到 12px；表格与汇总卡的数字走 `tabular-nums`，每秒刷新时数字宽度不再抖。
  托盘那一侧的弱化色 `_MUTED` 用同一把尺量，同样过 AA；面板底部状态行与详情窗字段名从前是 `#666`（3.18:1），也一并换成 `_MUTED`，
  并有源码守卫盯着：再出现 `#666`/`#555566`/`#99a` 或任何 `fg`/`foreground` 写死的色值不过 4.5:1，测试就红。
- **托盘表格隔行浅色**: 现在奇数行垫一层比表格底亮 50.1% 的浅底：`#26263a`，就是面板里“抬起面”（按钮 / 表头）已经在用的那个色，不引入新色值。
  隔行是只设 `background` 的 tag，热度色是只设 `foreground` 的 tag，两者叠在同一行各管一头 —— 以后换底色不会洗掉热度色。
  实测各热度前景在隔行底上 `_FG` 10.88:1 / hot 5.33:1 / warm 8.08:1 / cool 7.56:1，全部仍过 WCAG AA 4.5:1；再亮一档（`#33335c`）hot 只剩 4.28:1，用例会当场红。筛选后剩下的行从第一行重新隔行，不会错位半行。
  Web 侧的守卫同样升级成全量扫描：`_PANEL_STYLE` 里每一条 `color:` 声明都要在页面底色与卡片底色上都过 4.5:1，
  不再靠逐个选择器点名 —— 以后再加一档灰、改一个色值，不过线当场就红。

命令行方式：

```powershell
# 列出显卡与当前核显占用（含每进程专用显存）
# 采样窗口跟 config 的 interval_seconds 一致，不写死 1 秒（否则同一个进程在
# --list 和面板里能差出数倍）
python gpu_monitor.py --list

# 持续监控（控制台模式，读取同目录 config.json）
python gpu_monitor.py

# 换一份配置文件（如游戏/日常各存一份，托盘/监控都读同一路径）
python gpu_monitor.py --config "D:\gpu-configs\game.json" --tray

# 托盘模式（后台监控 + 托盘图标 + 实时面板）
python gpu_monitor.py --tray

# 手动把某个 exe 设为独显 / 撤销
python gpu_monitor.py --set "D:\Games\game.exe"
python gpu_monitor.py --unset "D:\Games\game.exe"

# 查看所有已迁移的程序 / 一键清空（带确认）
# --status 读不到注册表时会说读不到, 不假扮"没有任何设置";
# --unset-all 报"已清除 N/M 项"并点名没清掉的那几个
# --unset 单个文件时三种结局分开说: 已清除 / 本来就没有独显设置 /
# 清除失败(权限被限制?), 不再用一句“无设置或清除失败”把失败说成没设过
# --set 写完会回读确认: 值没落地(杀软/策略拦下)时报
# “设置未生效”, 不会让你照着一句假成功去白重启程序
python gpu_monitor.py --status
python gpu_monitor.py --unset-all
```

## 配置（config.json）

`config.json` 是**本机运行期文件**：程序启动时按下面这张表的默认值补齐，
托盘/设置窗改动的结果也写回它，因此它已在 `.gitignore` 里、不随仓库分发。
删掉它只会回到默认值，手动改也是安全的（写坏时监控沿用当前配置，见下）。

| 字段 | 默认 | 说明 |
|---|---|---|
| `threshold_percent` | 50 | 核显利用率超过该百分比视为高占用 |
| `vram_threshold_mb` | 1024 | 核显显存(专用+共享合计)超过该 MB 也触发迁移（0 = 关闭），适合 Stable Diffusion / 本地大模型等吃显存程序 |
| `sustain_samples` | 5 | 连续超标多少个采样周期才迁移 |
| `interval_seconds` | 5 | 采样周期(采样窗口与周期等长, 不存在看不见的盲区); 手改超过 60s 会夹到 60, 防一个手误把监控/`--list` 挂死 ; 设置窗“采样周期 秒”格可改, 保存后下一轮生效 |
| `auto_restart` | false | 迁移后自动结束并重启该进程（慎用，进程会中断） |
| `auto_restart_processes` | [] | 只对这些进程自动重启；留空 = 对所有超标进程生效 |
| `ai_processes` | [] | AI 名单补充(四层识别的第 1 层): 这些进程永不省电切回/自动重启（重启会丢掉已加载的模型）；第 2 层认安装目录、第 3/4 层认显存，见 `protect_vram_mb` |
| `protect_vram_mb` | 2048 | 显存兜底(第 3/4 层): 进程独显专用显存、或 python*.exe 持有的 GPU 显存(专用+共享) ≥ 该值就按 AI 保护（0 = 关闭）；第 4 层故意只收窄到 python*.exe，游戏/浏览器再大的显存也不误伤 |
| `confirm_mode` | false | 迁移前弹窗询问；选择“忽略”的进程会记住，不再询问 |
| `ignore_processes` | [] | 确认模式下被忽略的进程名（也可手动编辑） |
| `exclude_processes` | [] | 按进程名排除，如 `["chrome.exe"]` |
| `exclude_defaults` | true | 启用内置排除名单(dwm/explorer 等 16 个常驻组件, 误迁会拖慢桌面) |
| `exclude_full_paths` | [] | 按完整路径前缀排除 |
| `force_igpu_names` | [] | 手动指定哪些显卡名按核显处理（自动判定失败时用） |
| `notify` | true | 迁移成功/失败时弹 Windows 右下角通知（勿扰模式下收进通知中心） |
| `notify_fullscreen_ignore` | true | 前台全屏(游戏/视频)时不弹通知, 收进通知中心 |
| `power_aware` | true | 电源感知: 用电池时自动切省电策略(阈值降到 battery_threshold_percent) |
| `battery_threshold_percent` | 40 | 电池供电时的迁移阈值 |
| `nvml_temp` | true | 独显温度监控(NVML, NVIDIA 驱动自带; 源码态读温度跑在隔离子进程里) |
| `temp_limit` | 85 | 独显温度超过该值弹提醒(摄氏度) |
| `web_port` | 8787 | 本地 Web 面板端口, 0=关闭 (http://127.0.0.1:端口) |
| `power_saver_notify` | false | 独显上持续低负载的程序提醒可切回核显省电 |
| `power_saver_idle_percent` | 10 | 独显利用率低于该值视为低负载 |
| `power_saver_samples` | 60 | 低负载持续多少个采样周期才提醒 |
| `power_saver_auto` | false | 独显低负载时自动把独显设置改回核显(省电; 只提醒不改见 power_saver_notify) |
| `normalize_total` | false | true=按**每块显卡**分别把进程总和压到 100%(单进程读数会缩水, 但独显再忙也不会把核显的读数按比例压小); false=任务管理器口径, 单进程最准 |
| `history` | true | 每 10 秒记录核显总占用到 history.jsonl |
| `game_processes` | [] | 游戏名单: 自动确保独显+免打扰+时长统计 |
| `log_to_file` | true | 同时写 gpu_monitor.log（超过 5MB 自动滚动为 .log.1） |
| `hotkeys` | `{"panel": "ctrl+alt+g", "pause": "ctrl+alt+p"}` | 全局热键（托盘模式下生效）：开实时面板 / 暂停恢复监控。留空或删掉某个键即停用它 |

## 其它

- **全局热键**（托盘模式）：`Ctrl+Alt+G` 打开实时面板，`Ctrl+Alt+P` 暂停/恢复监控。
  热键配在 `config.json` 的 `hotkeys` 里，改完要重启监控才生效。只有托盘模式会注册，
  因为热键回调要用到托盘自己的窗口/菜单逻辑。
- **单实例**：托盘、`--tray`、`--ensure` 和命令行持续监控共用同一个互斥体，
  已经有了一个实例在跑，第二个只会打印"已有 GPU 监控实例在运行"然后退出 ——
  避免两个循环同时写注册表和 history.jsonl。`--list` / `--set` / `--status`
  这类一次性命令不受限制。
- **确认弹窗有超时**：`confirm_mode` 的模态框 120 秒没人应答就按"本轮不迁移"处理，
  不会一直按住监控线程（采样、历史、托盘图标都会跟着停）。
- **配置写坏不会带跑监控**：数字写成字符串、越界、列表写成了字符串，
  都会在加载时收敛成默认值/合法值并记一行日志（见 `merged_config`），
  不会等它在循环里抛 TypeError。
- **迁移效果闭环**：自动重启成功后会观察新进程实际挂在哪块显卡上 ——
  落在独显上弹"迁移验证成功"；20 秒宽限后仍在核显上弹"迁移未生效"；
  90 秒内一次 GPU 活动都没有也会说"迁移未确认"，不静默丢单。
  写完注册表还会回读确认值落了地: 没落地就报"迁移未生效",不会拿一句假成功让你白重启(托盘详情窗的"设为独显"、命令行 `--set` / `--unset`、省电模式自动切回核显同一把尺子)。
- **迁移失败会说实话**：写注册表和自动重启是两件事。注册表写失败才算迁移失败；
  只有重启失败时，日志和通知都会说"已设为独显，自动重启失败请手动重启"。
- **注册表读不到不等于没有**：`--status` / `--unset-all` 打不开键时会说读不到，
  不把"一条也没读到"播报成"当前没有任何 GPU 首选项设置"；`--unset-all` 清掉几项
  就报 `已清除 N/M 项`，并点名没能清除的那几个（权限被限/文件被占用时看得见）；
  `--set` 写失败也报"设置失败 + 原因"不甩 traceback; 写完还要回读确认值真落了地(否则报"设置未生效"), `--unset` 删完同理回读一次, 不拿"已清除"收尾。
- **配置热重载**：监控运行中修改 config.json 保存即自动生效，无需重启。
  例外：`web_port` 与 `hotkeys` 在启动时一次性注册，改完要重启监控进程
  （日志会提示 `需重启监控后生效`）。

- **汇总卡上下内边距和 Web 面板对上, 且上下对称**: 托盘那六张卡原来是 `pady=(5, _CARD_LABEL_GAP)` / `pady=(0, 5 - _CARD_LABEL_GAP)` —— 标签离卡顶 5px、数值离卡底 3px, 合计 8px, 而浏览器里 `.card{padding:9px 16px}` 是上下各 9px: 同一张卡在托盘里比 Web 矮 10px, 而且自己上下还不一样宽。更难看的是两处注释都写着"早就按 9px 对齐了" —— 那个"总纵向 padding 恒为 8"的装置把 9 这个意图吃掉了, 改 `_CARD_LABEL_GAP` 还会让不对称加剧。现在提成命名常量 `_CARD_PAD_Y = 9` / `_CARD_H = 66`, 上下都落回 9, `_PANEL_MIN_H` 跟着 634 -> 644。

- **设置窗与详情窗的外层内边距收成同一把尺 `_DIALOG_PAD_X/_DIALOG_PAD_Y`, 顺带修掉三处跟 `_BLOCK_GAP` 脱钩的测试镜像**: 两个对话框原来各写一套 —— 设置窗 `padx=12/pady=8`、详情窗 `padx=14/pady=10`, 而且都是同一个提交里带进来的, 没有任何理由。两个对话框差 2px, 用户在两个窗之间来回时看得见: 左边缘不在同一条竖线上。现在提成 `_DIALOG_PAD_X = 12` / `_DIALOG_PAD_Y = 8`(取设置窗那一套, 较小的), **设置窗因此一个像素都不动**, 只有详情窗每边收 2px —— 而它是吃宽度的那一个(要显示没空格的长路径), 收 2px 正好多给它 4px 内容宽, 右列折行宽度的余量从 6px 涨到 10px。

- **顺手修掉一处被甩开的注释**: `_BLOCK_GAP` 的注释原本贴在常量上方, 后来 `_ROW_H` / `_FORM_ROW_PITCH` 两块插进两者之间, 注释被甩到 30 行开外、正好压在 `_ROW_H` 的注释上头 —— 读代码的人会把「面板四个区块之间的间距...每处都是 4px」当成在说表格行高。§162 把它搬回常量旁边。
- **弹泡的两份实现收成同一把尺 `_TIP_PAD_X/_TIP_PAD_Y/_TIP_GAP_Y/_TIP_EDGE_GAP`**: 汇总卡 tooltip(`_bind_tip`)与表头列头 tooltip(`_bind_tree_tip`)是同一套视觉的两份实现, 却各写了一份裸数字 `8/6/4/8` —— Label 的 `padx=8, pady=6`、弹泡离控件的 `+4`、离屏幕右缘的两处 `8`。副本漂开没有任何人会发现: 没有任何一条守卫同时看这两份, 而它们在屏幕上是同一个东西 —— 用户不会因为悬停的是表格列头就接受一个更胖、离控件更远的弹泡。现在四处提成命名常量, 两处 `_show` 各自接回。
  抽常量而不是让两处写同一个数: 这四个数在这一轮已经跟着调过几处, 两处硬写同一个数等于把同一件事说两遍, 下次改一定只改一边。新增 `TrayPanelStatusFloor.test_the_two_tooltips_share_one_pad_and_gap`, 四处使用点逐处钉(每处只查自己的, 合起来查的话其中一处退回裸数字会被另一处掩盖过去), 外加真渲染按**差分量**钉常量对 Label 尺寸的贡献: 同一个文本/字体/折行宽度下, `padx=_TIP_PAD_X, pady=_TIP_PAD_Y` 的 Label 比显式 `padx=0, pady=0` 的宽 `2*_TIP_PAD_X`(16)、高 `2*_TIP_PAD_Y`(12)。

- **读温度那句原生调用搬进了隔离子进程**: 本机 `gpu_monitor_crash.log` 里 165 段
  access violation 的首帧全落在 `nvmlDeviceGetTemperature` 那一行上（见上一条对
  faulthandler 的说明）—— C 级访问冲突能不能被 Python 接住取决于被调方内部有没有
  SEH，不取决于 Python，所以这是真会发生的事，不是理论风险。现在源码态下每次读
  温度都起一个干净的子进程（隐藏子命令 `--nvml-probe`，跑同一个源文件，
  `CREATE_NO_WINDOW` 不闪控制台），父进程只认它的退出码和 stdout：子进程被内核干掉
  时死的是它，监控循环和托盘照常活着，那一轮按普通读取失败处理（面板有上一段的暂留
  逻辑兜着）。探针起不来 / 超时 / stdout 不是数字，一律当“没隔离”，退回进程内直读，
  功能不丢也不外抛异常；探针自己走 `isolate=False`，不会子进程生孙进程。只在源码态
  隔离：打包版 `sys.executable` 就是 exe，每次起子进程都要重新解压 onefile 镜像（实测
  4 秒以上），而温度每 10s 读一次，隔离会把采样周期整个吃光，所以那种环境下老老实实
  进程内直读。实测子进程读一次 ~0.3s，进程内直读 ~42ms。
- **PDH 通配展开的缓冲区有了上界**：`expand_counter_paths` 的缓冲区是照 `PdhExpandWildCardPathW` 报回的字符数现分配的（`size.value + 1024` 余量，防两次调用之间实例数增长）。对这个数不设上界，等于让一个外部 API 的返回值决定本进程一次分配多少内存：报回荒谬值时 `create_unicode_buffer` 直接 `MemoryError`，采样线程硬死，连 `_dbg` 那种"留一行痕迹"的机会都没有。现在超过 1M 字符就 `OSError` 拒绝分配，且不重试（荒谬的长度重试五次还是荒谬）。本机实测一次展开 507 条 GPU Engine 实例路径 / 54,943 字符，上限是它的约 19 倍 —— 拦不到正常用量，只拦荒谬值。

  注册表写入与进程枚举都是打桩的，不会动到本机 GPU 首选项）。
每条新行为都配了"只回退这一处就让它变红"的非空性验证，见 `HANDOFF.md`。

## 实现原理

- **占用采样**：PDH 性能计数器 `\GPU Engine(*)\Utilization Percentage`，
  实例名形如 `pid_1234_luid_0x00000000_0x00013502_phys_0_eng_0_engtype_3D`，
  按进程 (pid) 聚合每个引擎的利用率。
  PDH 读的是"窗口内引擎活跃时长 / 墙上时长"的比例，所以采样窗口与
  `interval_seconds` 等长：周期调成 5 秒就看满 5 秒，不会每 5 秒只看 1 秒、
  中间 4 秒的峰值整段漏掉（老代码固定 1 秒窗口，实测周期 3 秒时占空比只有
  49%，`interval_seconds` 调大反而看得更少）。
- **显卡识别**：取实例里的 LUID，通过 `gdi32!D3DKMTOpenAdapterFromLuid` +
  `D3DKMTQueryAdapterInfo`（查询类型 65）获取显卡名称。
  （不使用 DXGI——部分机器上 `CreateDXGIFactory1` 会返回 E_NOINTERFACE。）
- **核显/独显分类**：名称启发式（Intel UHD/Iris/Arc Graphics → 核显，NVIDIA/Arc(A/B 型号)/Radeon RX → 独显，
  WARP/虚拟显示适配器忽略），辅以 `Win32_VideoController` 专用显存大小；
  自动判定失败时可用 `force_igpu_names` 手动指定。
